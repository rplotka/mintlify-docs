description: "Query academic calendar events by semester code, retrieve course-week schedules, and subscribe to an iCal feed for deadline and class reminders."

The schedule API exposes two layers of calendar data. The academic calendar endpoint returns semester-level events such as when classes start, holidays, and finals periods. The iCal subscription endpoint generates a personal `.ics` feed that combines your course schedule and assignment due dates, compatible with any calendar application that supports iCal subscriptions.

## Get academic calendar for a semester

Returns all academic calendar events for a semester identified by its code. This endpoint is public — it does not require authentication — and is used by other services to build course schedules. The `includeInformational` parameter controls whether informational-only events (those that do not cancel or affect classes) are included.

```
GET /api/schedule/semesters/:semesterCode/calendar
```

<ParamField path="semesterCode" type="string" required>
  The semester code, for example `SP2026` or `FA2025`. Codes follow the pattern `SP` (Spring), `FA` (Fall), or `SU` (Summer) plus a four-digit year.
</ParamField>

<ParamField query="includeInformational" type="boolean">
  When set to `false`, only events that affect class meetings (i.e., `affectsClasses: true`) are returned. Defaults to `true`, which includes all event types.
</ParamField>

<CodeGroup>
```bash cURL
# All events including informational
curl "https://lms.plotka.me/api/schedule/semesters/SP2026/calendar"

# Class-affecting events only
curl "https://lms.plotka.me/api/schedule/semesters/SP2026/calendar?includeInformational=false"
```

```js JavaScript
const res = await fetch(
  "https://lms.plotka.me/api/schedule/semesters/SP2026/calendar?includeInformational=false"
);
const { data, meta } = await res.json();
```
</CodeGroup>

<ResponseField name="data.semesterCode" type="string">
  The semester code you queried.
</ResponseField>

<ResponseField name="data.classesStart" type="string">
  ISO 8601 datetime for the first day of classes.
</ResponseField>

<ResponseField name="data.classesEnd" type="string">
  ISO 8601 datetime for the last day of classes (before finals).
</ResponseField>

<ResponseField name="data.finalsStart" type="string">
  ISO 8601 datetime for the start of the finals period.
</ResponseField>

<ResponseField name="data.finalsEnd" type="string">
  ISO 8601 datetime for the end of the finals period.
</ResponseField>

<ResponseField name="data.calendarEvents" type="array">
  Ordered list of calendar events, sorted by date ascending.
</ResponseField>

<ResponseField name="data.calendarEvents[].eventType" type="string">
  The type of calendar event. Common values are listed below.
</ResponseField>

<ResponseField name="data.calendarEvents[].affectsClasses" type="boolean">
  `true` when the event cancels or changes class meetings. Use `includeInformational=false` to filter to only these events.
</ResponseField>

<ResponseField name="data.calendarEvents[].endDate" type="string | null">
  End date for multi-day events such as `BREAK`. `null` for single-day events.
</ResponseField>

<ResponseField name="data.calendarEvents[].dayOfWeek" type="number">
  Day of the week as a number: `0` = Sunday, `1` = Monday, …, `6` = Saturday.
</ResponseField>

### Calendar event types

| `eventType` | Description |
|-------------|-------------|
| `CLASSES_START` | First day of instruction for the semester |
| `CLASSES_END` | Last day of instruction |
| `HOLIDAY` | University-observed holiday; classes do not meet |
| `BREAK` | Multi-day break period (e.g., Spring Break) |
| `FINALS` | Finals examination period |
| `NO_CLASS` | Individual day with no classes (e.g., snow day) |
| `INFORMATIONAL` | Informational notice; does not affect classes |

## Get schedule for a course semester

Returns the week-by-week teaching schedule for a specific course semester. The weekly data includes schedule items, resource links, and topics. Students must be enrolled; unpublished schedules return `403` for unauthenticated requests.

```
GET /api/schedule/:courseSemesterId
```

<ParamField path="courseSemesterId" type="string" required>
  The course-semester ID from `GET /api/courses/:slug/:semesterCode`.
</ParamField>

<CodeGroup>
```bash cURL
curl https://lms.plotka.me/api/schedule/clx1cs01 \
  -H "Authorization: Bearer <token>"
```

```js JavaScript
const res = await fetch("https://lms.plotka.me/api/schedule/clx1cs01", {
  headers: { Authorization: `Bearer ${token}` },
});
const { weeks, semester } = await res.json();
```
</CodeGroup>

**Response (200)**

```json

  "data": {
```

## iCal subscription feed

Generates a personal iCal (`.ics`) calendar feed containing your class meetings and assignment due dates. Subscribe to this URL in Google Calendar, Apple Calendar, Outlook, or any other iCal-compatible application to keep your schedule synchronized automatically.

The feed uses token-based authentication — no `Authorization` header is required. Obtain your personal subscription token from the user preferences in the Learning In Stride web app.

```
GET /api/hub/schedule/ical/:token
```

<ParamField path="token" type="string" required>
  Your personal calendar subscription token. Retrieve it from your account settings in the Learning In Stride web app. Keep this token private; anyone with it can read your schedule.
</ParamField>

```bash
# Add this URL to your calendar application
https://lms.plotka.me/api/hub/schedule/ical/your-subscription-token
```

The endpoint returns a `text/calendar` response with `Content-Disposition: attachment; filename="mylms-schedule.ics"`. The generated calendar includes:

- Class meeting events for each course you are subscribed to, with location and time
- Assignment due-date events for upcoming homework, projects, and labs
- Recurring event rules where applicable

<Warning>
  Your subscription token grants read access to your personal schedule without requiring a password. If you believe your token has been compromised, regenerate it from your account settings — your old subscription URL will stop working immediately.
</Warning>

<Note>
  The iCal feed reflects the current semester only. If no active semester is found, the feed returns an empty calendar rather than an error, so existing subscriptions do not break between semesters.
</Note>
